# Recursive native PHP packages

The [execution record](php-recursive-packages-20260923.json) binds original
Composer archives, generated sources, independent callers and fresh rebuilds.
Installed, reproduction and shared-loading gates pass. Final acceptance still
requires shared-backend regressions, source-lineage verification and the complete
repository suite. The type inventory has not promoted native PHP recursive cells.

## Installed calls

Ordinary Lean source and independently reviewed IR each produce a Composer-only
release with eighteen public functions. The uninhabited `Never` family rejects
invalid inputs without entering Lean. The other functions execute compiled Lean
through generated PHP functions and readonly value classes. No public C package
or GMP facade is added.

Each test installs the original ZIP offline with an empty Composer home and
cache. Composer resolves the pinned Brick Math dependency. The test removes
author inputs and the installation project, relocates `vendor`, then runs weak
and strict callers twice with no compiler or native-path overrides. Each caller
passes 1,457 assertions and 35 rejection checks. It verifies all nineteen scalar
representations, nominal constructors, aliases, recursive and mutually recursive
values, nested options and results, wide constructors, depth limits and copied
results. The separate cold-call gate passes without the FFI extension.

The archive carries its compiled component, shared runtime and private adapter.
Library hashes are checked before mapping. Corrupting any of the four native
assets rejects before loading Lean; the tamper fixture restores the original
bytes and permissions. The public API contains no native handles or symbols.

## Identity and reproduction

The package audit regenerates every public and private source file. Build checks
reject three graph-receipt mutations and four re-signed adapter-source changes.
Compiler-free reassembly reproduces the original ZIP. Two independent fresh
native builds reproduce the exact archives exercised by installed consumers,
including their compiled Lean binaries and finite-layout identities.

## Shared runtime

Two recursive packages and an ordinary package install together in one offline
Composer project. One recursive release also targets C++. Both call orders
observe one runtime initialization, three component initializations and eight
expected native-library mappings. Post-fork calls reject. Retiring the shared
runtime disables all three APIs while previously copied PHP values remain usable.

Two genuine builds of one component coordinate exercise duplicate and conflict
handling in both orders. The probe installs both original archives but autoloads
only one public API: PHP cannot declare the same functions and classes twice.
It then checks the shared native registry using the second archive's original
evidence. Duplicate identities reuse existing mappings; conflicts reject before
mapping the second component and leave the first usable.

Reproduction commands appear in the
[contributor guide](../contributing/testing.md#recursive-composer-packages).
PHP-Wasm recursive conversion, structured callable payloads and explicitly owned
resource-containing aggregates remain separate implementation work.
