# Rust host members: compiler evidence

`npm run test:rust-host-source` checked an ordinary Lean project importing
`LeanBridge.Host.Rust`, then rebuilt it from an independent review of the
exported API. Both routes produced identical public IR and module interfaces.

| Checked output | SHA-256 |
| --- | --- |
| Public binding IR | `fc9aa99606b981f12ab64283bfdaf66370c23f8e19ff470ef9e2ced903577eb8` |
| C generated by Lean for the Rust host import module | `de96b5e18e25dabf6c62ff1fad9b0277389a64101f44318c7e4ad7b3c0e83596` |

The [test](../../tests/helpers/native-host-import-check.mjs) checked the
constructor, mutable property, method and leased result, including the
actual `lean_bridge_host_rust_box_set_level` symbol. A member's declared
`RustHostError` and Lean's `IO.Error` remained distinct. A mapped `EIO`
failure had its own error site; a returned `Except` remained a value.

Negative cases rejected changed captured imports, omitted dependencies,
cross-language symbols, scheduler selection, a stale review, and local source
shadowing the generated Rust module. The package builder still refuses
Cargo host imports: this gate does not link a Rust provider or exercise an
installed crate. Those are separate from the existing Rust task and IO
packages.
