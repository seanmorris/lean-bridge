# Compiled Java and Kotlin Lists

VO1219 adds copied `List T` inputs, results and record fields to prepared Maven
packages. Ordinary-source and independently reviewed-IR builds compile the same
27-export Lean fixture. Java and Kotlin consume the same JAR on each path.

Java uses typed arrays, including primitive arrays for primitive elements.
Kotlin uses the corresponding primitive or reference arrays: `LongArray` for
`List UInt32`, `Array<BigInteger>` for `List Nat`, and `Array<LongArray>` for
`List (List UInt32)`. Lists retain distinct Binding IR and native C identities.
They preserve empty values, order, duplicates and nesting. Mutable returned
values have independent storage.

## Installed validation

```sh
LEAN_BRIDGE_JVM_LIST_TEST=1 node --test tests/jvm-lists.test.mjs
node --test tests/jvm-list-contract.test.mjs
```

The [machine-readable record](jvm-lists-20260920.json) binds archive, receipt,
source, compiler, runtime and deployed-file hashes. Each path passes 91,674
Java assertions and 91,696 Kotlin assertions with JDK 22.0.2, Kotlin 2.2.0 and
Maven 3.9.11. Both consumers compile with warnings treated as errors.

The suite removes the producer before installing its original JAR and POM
offline into empty Maven repositories. Consumers use only the resolved prepared
dependency. Checks cover all nineteen primitive elements, exact 5,121-bit
integers, fixed-width bounds, floating-point edge cases, Unicode and embedded
NUL, mixed Lists and arrays, options, both result branches, binary products and
record fields. A 24-level fixture checks every empty level. Mutation checks
verify independent inputs and sibling results. Four concurrent callers retain
independent state. Invalid payloads and oversized inputs or outputs reject,
then later calls succeed. A 30,000-element generated List exercises traversal.

Twelve invalid programs per language fail with specific compiler diagnostics.
They cover wrong element types, scalar or collection containers, array nesting,
boxed arrays, missing option wrappers, incorrect product payloads, result
assignments, integer overflow and incorrect integer representations.

Each consumer runs twice from a relocated deployment after its sources,
compiler inputs and Maven cache are removed. The generated runtime contains
only `java.base`; Kotlin adds its standard-library JAR. No compiler is available
through PATH. Both executions reproduce the same results and native-library
hashes. Deployment and runtime hashes remain unchanged. Normal shutdown removes
all privately extracted native libraries.

## Cleanup and malformed output

A separate instrumented projection uses the verified generated Java sources
and the same compiled native libraries. It leaves the release JAR unchanged.
Per source path, 263 injected conversion and allocation failures verify closed
arenas, one output clear per native call and successful recovery. Sixteen
partial-input failures verify cleanup before Lean runs.

Eleven malformed-output checks reject excessive or negative lengths, missing
buffers, misalignment and an invalid nested List buffer. Poisoned empty buffers
are ignored. The output guards run before array allocation or element reads;
alignment follows the native element layout, including compound fields.
The record retains original and instrumented source hashes. Native allocator
fault checks remain in the [C/C++ List suite](native-lists-20260920.md).

JVM input copying has a 16 MiB accounting budget. Native copying shares a
separate 16 MiB budget across inputs and outputs. Per-sequence output guards
limit each allocation. These checks do not bound every JVM allocation or Lean
working memory. Types have a 32-level nesting limit. Local acceptance uses
Linux x86-64 with glibc floor 2.36; CI builds supported 2.38-floor packages.

This milestone promotes twelve profile/path/position cells: List inputs,
results and fields in Java and Kotlin on both source paths. List callback
payloads, aliases with distinct runtime identity, arbitrary or recursive
variants and resource-containing copies remain separate work.
