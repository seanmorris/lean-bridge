# Docker-first canonical build evidence

## Result

`lean-bridge build` now produces one canonical release directory through Docker or native Nix:

```text
build/lean-bridge-release/
├── build-report.json
├── bundle/
│   ├── canonical-package.json
│   ├── compiled Wasm runtime and side modules
│   ├── generated JavaScript, PHP, Python, C, and Rust bindings
│   └── assurance, SBOM, provenance, schemas, locks, and docs
└── packages/
    ├── publication-index.json
    ├── provenance.intoto.json
    └── registry package archives or explicit omissions
```

The command selects Docker when its daemon responds. It falls back to native Nix when Docker is absent. `LEAN_BRIDGE_BUILD_BACKEND=docker` and `LEAN_BRIDGE_BUILD_BACKEND=nix` provide explicit policy. If neither tool exists, the command returns `blocked` before creating an output directory and prints one Docker or Nix installation path.

The output path must not exist. The builder writes into a generated staging directory, validates the canonical manifest and publication index, then renames the complete result into place. A failure removes only that generated staging directory.

## Pinned Debian builder

[`containers/builder/manifest.json`](../../containers/builder/manifest.json) records:

- Debian bookworm-slim by immutable image digest;
- Nix 2.24.11 by immutable image digest;
- the Dockerfile, entrypoint, Docker ignore policy, and Nix configuration hashes;
- one definition hash and expected reproducible image config hash;
- user, locale, timezone, source and output mount policies, and network policy; and
- the two authoritative flake outputs.

The final image uses Debian. It copies the Nix store closure from the pinned Nix image. It does not install or pin Lean, Emscripten, libuv, Node, PHP, Python, Rust, C compilers, or package backends. [`nix/wasm-toolchain.nix`](../../nix/wasm-toolchain.nix), `flake.lock`, and the flake outputs remain the only build policy.

The image build sets `SOURCE_DATE_EPOCH=1786261809`. Repeated local builds produce config digest `c4202ef2601394eeffe06d8a988e617d9cc990f28334ee51b4feb277c262a927`. Run its validation command with:

```sh
npm run build:builder-image
```

The manifest currently records `publicationStatus: local-reproducible` and no registry reference. Publishing this reviewed image to an OCI registry requires registry authority. A supplied `LEAN_BRIDGE_BUILDER_IMAGE` must use an immutable `@sha256:` reference.

## Read-only source and canonical flake

Docker mounts the project read-only. The entrypoint copies Git-visible files into a clean root-owned tree so Git ownership checks and ignored host build products cannot influence evaluation. It copies repository metadata when available, preserving the same revision identity as native Nix. Non-Git source trees use a clean path flake.

The entrypoint invokes only:

```sh
nix build --no-link --no-write-lock-file .#universal-release-bundle
nix build --no-link --no-write-lock-file .#release-rehearsal
```

The release rehearsal consumes the universal bundle. Package projection backends run without compilers and verify that copied core hashes equal the canonical artifact hashes. The build report therefore records `componentBinariesRebuiltByProjection: false` only after both outputs pass their existing validators.

The flake passes a fixed source date epoch into bundle assembly. Docker and native Nix no longer derive release bytes from checkout timestamps.

The reproducibility gate requires a clean committed source tree and compares every generated byte, including source revision provenance, before publication.
