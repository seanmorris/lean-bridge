# Compiled npm Lists, 20 September 2026

VO1219 adds `List α` to the shared compiler's copied-type model and Binding IR.
Prepared npm packages expose ordinary JavaScript arrays and TypeScript
`ReadonlyArray<T>`. Order, duplicates, empty lists and nesting are preserved.
The element type can be any of the nineteen supported primitives, an array,
List, acyclic copied record, Option, Except or binary product.

## Contract and transport

Binding IR retains `constructor:list` with one type argument. A review that
substitutes `array` fails reconciliation, even though both use host arrays.
The private compound ABI keeps the descriptor's constructor and uses the existing
ordered sequence slot layout. Scalar, callable, array-only and record-only
packages keep their existing ABI versions. No Lean cons tag or field offset
crosses the public interface.

Typed Lean adapters convert incoming arrays to Lists and returned Lists to
arrays. The output walker is tail-recursive and bounded to 1,048,577 elements.
That includes one element beyond the largest possible 16 MiB slot budget, so
oversized results fail rather than returning a truncated prefix. Nested values
still charge the same call-wide budget. This bounds transport copying, not the
algorithm's working heap inside Lean.

The boundary permits at most 32 container levels and 4,096 expanded type nodes.
Host arrays must have dense own data elements with no extra properties, getters,
typed-array substitution or cycles. Returned nested arrays, objects and byte
buffers own independent storage. They need no disposal. Budget failures clear
partial output and allow subsequent calls; traps or malformed output retire
the shared runtime.

## Installed execution

```sh
CHROMIUM_PATH=/usr/lib/chromium/chromium \
LEAN_BRIDGE_TYPE_CORPUS_BROWSERS=chromium,firefox,webkit \
node --test tests/component-lists.test.mjs
node --test tests/component-list-contract.test.mjs
```

The [execution record](npm-lists-20260920.json) retains archive receipts, source
and consumer hashes, browser versions and results for ordinary-source and
independently reviewed builds. Each build compiles 27 Lean exports and checks
their declarations against an independent catalog. The source project is moved
before installation. Consumers install offline with an empty npm cache and run
without compiler tools on PATH.

Both packages execute in Node and strict TypeScript. Chromium, Firefox and
WebKit each execute the same checks in a page, React and a dedicated worker.
Each JavaScript context passes 30,226 checks and 25 rejection cases.
The fixture covers all nineteen primitive elements, IEEE special values,
129-limb integers, Unicode and NUL, mixed Array/List nesting, Lists inside
Option/Except/products and record fields, and 24 nested Lists. Reversals and
branch-changing functions require actual Lean execution. Repeated oversized
outputs must reject and recover; returned mutable copies must remain independent.

Separate contract tests cover schema and arity checks, List/Array substitution,
recordless adapter generation, malformed slots, accessors, partial allocation
failure, cleanup and runtime poisoning. Their synthetic fault probes do not
count as compiled Lean execution.

## Remaining work

This milestone promotes List inputs, results and fields on both source paths in
the five npm profiles. Native and PHP-Wasm packages still reject Lists during
build admission. List callback payloads remain rejected; copied values cannot
contain callbacks or resources. Named-alias preservation, arbitrary and recursive
variants, and compound callables remain separate work under VO1219.

Historical corpus evidence is retained. New negative-build copies use an
unsupported `Sum UInt32 UInt32` instead of List; the oracle modules are unchanged.
