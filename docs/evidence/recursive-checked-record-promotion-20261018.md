# Recursive checked-record acceptance

The public support inventory now records installed acceptance for finite
recursive checked-record graphs across all seventeen consumer profiles. The
fixtures cover a self-recursive `Packet` record and a mutually recursive
`Envelope`/`Step` record-and-variant pair, transparent aliases, `Array` and
`Option` carriers, active variant branches, checked natural-number fields, and
closed `Fin 3` fields.

Every admitted lane retains ordinary-source and independently reviewed
packages. Generated adapters validate the complete finite graph in dependency
order, apply the constructor selected for each public site, erase proof fields,
preserve rejected caller values, recover on the next valid call, and return
copied results without proof constructors. The retained packages include
independent author builds, source-free offline installation, relocation, and
unchanged caller replay wherever the host permits those steps.

This acceptance is deliberately narrow. It covers the tested finite `Packet`
and `Envelope`/`Step` graphs, their aliases and carriers, and the recorded
checked fields. It does not establish arbitrary recursive graph shapes,
value-carrying receiver-dependent fields, other index kinds, open dependent or
zero-payload records, callbacks, owned positions, retained object identity, or
cyclic host-object inputs.
