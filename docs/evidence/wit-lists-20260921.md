# Installed WIT/WASI Lists

Prepared WIT/WASI packages accept copied Lean Lists as parameters, results and
record fields on ordinary-source and independently reviewed-IR paths. The
[machine record](wit-lists-20260921.json) binds the source, compiler metadata,
archives, receipts, parsed declarations, installed files and runtime libraries.
Base revision: `d3c2d5c`.

## Installed execution

Each path builds the independent 27-export List fixture. Compiler metadata,
parsed WIT and the compiled Component Model binary must match the signature
catalog. Lean Lists and Arrays retain distinct IR and native C types while
both use canonical WIT `list<T>` values.

The consumer installs the original archive offline after removing the producer
workspace. It compiles against the packaged public Wasmtime header, relocates
the application, and removes the handoff and installation project. Two runs
execute without compilers, Lean or runtime overrides. The five packaged native
libraries must load from the relocated directory; their hashes, the component
and the consumer executable remain unchanged.

Every run passes **721,296 assertions across 2,651 calls**, including **60
rejected calls** followed by successful recovery. The consumer checks:

- All nineteen primitive element types, integer endpoints, 5,121-bit Nat/Int
  magnitudes, IEEE normal/subnormal endpoints, signed zero, infinities, NaN
  classification, Unicode scalars, embedded NUL and binary data.
- Empty and singleton Lists, asymmetric reversals, duplicates, 24-level
  nesting with empty Lists at every level, List/Array mixtures and copied fields.
- Option presence, both asymmetric Except branches and ordered nested products.
- Independently owned arrays, byte buffers and branches. Results survive input
  destruction and session close; changing one result cannot change its sibling.
- Wrong host value kinds, malformed fields and branches, tuple arity, invalid
  Unicode/UTF-8, noncanonical integers, missing buffers, excessive counts and
  cyclic input values rejected before Wasmtime copies them.
- Input, native-output and Wasmtime-output conversion limits. Output failures
  leave the caller's result slot unchanged, dispose trapped stores and recover.
  A valid 30,000-element generated result passes after rejected calls.

The public consumer uses Wasmtime's value types and the packaged session API.
It does not call the private native adapter or inspect Lean cons-cell layouts.
Typed Lean helpers use `Array.toList` and a bounded List-to-Array traversal.

## Conversion probes

A separate synthetic probe passes AddressSanitizer, LeakSanitizer and
UndefinedBehaviorSanitizer. It does not execute Lean. Its **15,006 assertions**
cover four injected scratch-allocation failures, 1,172 input-budget failures,
812 output-budget failures, eleven malformed native outputs, two malformed
input buffers, one empty poison-pointer output and three unreadable inactive
branch payloads. Partial output and scratch storage are released. Tracked live
allocations return to zero before the next successful conversion.

Parser contracts check canonical List signatures, distinct native List/Array
identities, excessive type nesting, callback rejection and both sides of the
sixteen-flat-argument boundary. A mutated parsed result type must fail the
independent signature check.

## Reproduce

Use the [WIT author toolchain](../publish/wit-wasi.md#build-an-ordinary-lean-project):
Lean 4.32.2, Wasmtime 42.0.1 C API, wasm-tools 1.245.1 and a C compiler.

```sh
LEAN_BRIDGE_WIT_LIST_TEST=1 node --test \
  tests/wit-lists.test.mjs tests/wit-list-contract.test.mjs \
  tests/wit-list-conversions.test.mjs
node --test tests/wit-list-evidence.test.mjs
```

CI requires `build/lists/wit.json` and `build/lists/wit-conversions.json`.
The local installed run used GCC 12.2.0 and the explicit glibc 2.36 test override;
the supported CI package floor remains 2.38. No registry package was published.

## Limits

Type nesting stops at 32. Host conversions and native copying each have a
16 MiB accounting budget. Component scratch memory is capped at 64 MiB. These
limits do not bound all Lean or Wasmtime working memory. Lean words are 64-bit;
canonical component memory uses wasm32 addresses. The component requires the
included native host and is not a standalone WASI command.

Callers must supply valid C storage. Arbitrary dangling or misaligned C pointers
are not supported inputs. Wasmtime allocation APIs do not expose recoverable
out-of-memory errors. The sanitizer probes test the adapter's fallible scratch
allocations and budget failures separately from those infallible host APIs.

This milestone reaches **102/102** copied List parameter/result/field cells
across **17/17** profiles and both source paths. Callback payloads, aliases,
arbitrary/recursive variants and resource-containing copies remain separate
VO1219 work. The [cross-profile acceptance audit](lists-acceptance-20260921.md)
checks the completed copied List round against its requirements.
