# Per-site nominal Subtype conversion foundation

This milestone fixes a generator prerequisite for #1444. It does not admit new signatures or add installed-package support.

The previous native generator kept one checked conversion for each nominal type. Two uses of the same record with different Subtype constructors would therefore select whichever constructor appeared first. The public compiler and independent validators still reject that combination, so the diagnostic uses an explicitly hand-built, unadmitted model.

## Implementation

- Records and variants retain one erased payload mirror and one constructor-independent erasure function.
- A checked conversion with Subtype leaves has a name derived from the complete per-site refinement tree, including field and case order, nested choices and Fin bounds. Identical choices share a conversion.
- Result-only Subtype records and variants generate no checked conversion. An input without its constructor is rejected.
- Constructor-leaf validators retain record field, variant case and structural positions.
- Conflicting layouts for one nominal type fail generation. Fin-only conversions retain their existing names and generated bytes.

The changes are in `src/build/component-refinements.mjs` and `src/build/native-model.mjs`. Compiler admission, export configuration, Binding IR and host admission are unchanged.

## Source checks

`tests/helpers/nominal-subtype-conversion-tests.mjs` compiles generated adapters against `tests/fixtures/nominal-subtype-conversion/NominalConversion.lean` with pinned Lean 4.32.2. It checks two constructors that normalize the same Nat differently and reject different ranges.

The three selections are forward export order, reversed export order and a result-only model. They check 17, 17 and 2 propositions, respectively. These cover repeated nominal types in separate exports, two parameters and nested fields; active and inactive variant branches; nested Array/Option/Except values; late constructor and Fin rejection; and erasure of Lean-produced values. Thirty checks use `decide`; the six Array execution checks use `native_decide`. Generated nullary helpers retain four existing binder warnings per selection.

The seven focused tests passed without skips. The Fin-only generated adapter snapshot remains `1ce38835771c829da75ad5666d4e1a2aa180be6124b6405dcdc7a9238886fa0c`.

Reproduce the source checks:

```sh
LEAN_BRIDGE_NOMINAL_SUBTYPE_CONVERSION_TEST=1 \
  node --test tests/helpers/nominal-subtype-conversion-tests.mjs
```

The registered native Subtype suite imports these tests. Its C profile and the existing structural-extractor flag also enable the Lean source check. This is generator and source-compilation evidence, not ordinary/reviewed author acceptance or installed-package acceptance.

Local original reports are retained under `build/vo1444-nominal-conversion-source-r3/`. The first source run exposed existing nullary-helper warnings in an over-strict test assertion. The second exposed Array reductions that require native evaluation. Both failed logs remain separate from the successful third run.

## Remaining implementation

Per-site constructor decisions must still travel through ordinary configuration, fresh Lean extraction, reviewed Binding IR and source reconciliation. Nominal type caching must preserve different choices within the same parameter as well as across exports. Host validators must check the selected field or active variant case and report the actual rejected path. Fresh ordinary/reviewed installed-package checks, recurring CI and support documentation follow that wiring.

Callback, owned, recursive and broader generic/dependent Subtype combinations remain open under #1444. This prerequisite does not close them or #1220.
