# Recursive callbacks in PHP-Wasm

Both ordinary-source and reviewed-IR builds install and execute recursive PHP
callbacks and returned `LeanClosure` owners. Original npm/runtime archives and
Composer ZIPs run offline after the author projects are removed. The tested PHP
8.4 host uses wasm32; native PHP acceptance has a [separate record](php-recursive-callables-20260926.md).

The [execution record](php-wasm-recursive-callables-20260926.json) contains the
original reports and terminal logs. The [integration record](php-wasm-recursive-callable-integration-20260926.json)
binds the source changes, predecessor records and four inventory cells.

## Installed packages

Each source path builds a 33-export package with 18 callable signatures and a
98-export mixed package with 59 signatures. The mixed package includes all
nineteen primitive families and sixteen-argument Unit callbacks and closures.

The four packages pass 48 Node executions across embedded, Composer-autoloaded
and bundled APIs, startup/lazy loading, and weak/strict PHP callers. Sixteen
Chromium arrangements each run in two fresh contexts. Every caller repeats
twenty requests. Invalid lazy calls load no libraries; valid calls load exactly
one component and one runtime, with no repeated DSO loading.

Base callers pass 1,130 checks and 388 rejections. Mixed callers pass 1,249 checks,
including 119 primitive checks. All nine copied shapes preserve distinct input,
reply and captured values. The exact documentation Lean definitions compile;
sixteen Composer executions of the documented PHP example print `42`, `20`, `42`.
Reassembly and relocated installed-file hashes remain unchanged.

## Failure and ownership checks

Separate instrumented adapters compile fresh Lean and execute on the actual
wasm32 host. These probes do not replace the original installed-package runs.
Each weak/strict caller passes:

- 12,752 assertions, including 278 borrowed-callback and 180 owned-closure
  allocation failures, recovery, 4,096 live closure slots and 8,192 reuse cycles.
- 647 ownership assertions, including 327 invalid, expired or wrong-signature
  callback contexts, six uint64 lease-generation checks, deferred active close
  and three context-exhaustion rejections. Tokens remain native uint64 values
  owned by Zend resources, never 32-bit PHP integers.
- Five aborted requests covering PHP `exit()`, Zend longjmp, nested calls with
  a live closure and reply-destructor aborts. The same Wasm instance recovers
  after request refresh. Hard bailouts match a raw-host control's status 1;
  PHP exit reports status 0.
- 476 partial Zend string/array construction aborts across borrowed and owned
  paths, each followed by cleanup checks and healthy execution.
- Eighteen nested callback reply checks before Lean copies the payload, plus
  eight malformed-result cases with retirement and disposal checks.

All tracked native/Zend allocations, native identities, borrowed contexts and
call depth return to zero. A premature reply-release mutant fails at
`callback_reply_storage_expired` before Lean reads invalid storage. A missing
retirement mutant fails at `malformed_output_retires_runtime`. Both report PHP
status 2, not a Wasm trap. Active-close observation changes only the private PHP
invoke closure; the Zend resource and native downcall remain real.

These probes found two defects: impossible spans were classified as budget
failures before pointer validation, and restoring PHP 8.4's internal exit object
through the public Throwable API caused a fatal error. Callable walkers now
check spans first; cleanup restores the exception with
`zend_throw_exception_internal`. Copied-only generated adapter bytes remain
unchanged. Original installed recursive copied-value and acyclic callable
packages pass again on both authoring paths.

## Bounds and remaining work

Conversions allow 128 levels, 262,144 visited values and separate 16 MiB native
and accounted PHP-storage budgets. Reentry allows 64 active calls. These limits
exclude Lean working memory and PHP object overhead. Borrowed callbacks expire
when their synchronous call ends; returned closures require explicit ownership.

The pinned PHP-Wasm host cannot start Fibers because it lacks `getcontext`.
Native-width wrapper tests exercise that guard; no Wasm Fiber execution is
claimed. WIT/WASI recursive callback acceptance and explicitly owned resource
aggregates remain work under VO 1219.

Run the installed gates with:

```sh
npm run test:php-wasm-recursive-generated
npm run test:php-wasm-recursive-packages
```

The consumer CI job runs both gates and uploads their three JSON reports. The
default contract suite checks the frozen evidence and rejects incomplete runs,
altered generated bytes, missing browser assets, forged cleanup and unrelated
source edits. Inventory version `0.106.0` records 4,826 installed cells out of
6,562; this milestone adds only four PHP-Wasm recursive callback cells.
