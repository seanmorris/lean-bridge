# Char through prepared npm packages

VO1218 adds Lean `Char` to the shared Binding IR and the npm scalar transport. The milestone starts from `80a9846`; the type inventory binds the changed source files and exact archives by SHA-256.

## Representation

JavaScript and TypeScript use a `string` containing exactly one Unicode scalar. This includes NUL, supplementary-plane characters such as `🌱`, and standalone combining characters. Empty strings, multiple scalars, unpaired surrogates, boxed strings and non-string inputs fail with `TypeError`. The adapter does not normalize text or split grapheme clusters.

The scalar frame adds tag 16 without changing existing tags. It carries the code point in the complete 64-bit slot, then calls Lean's compiled `uint32_t` representation. Both the host and compiled Wasm boundary reject surrogate values, values above `0x10FFFF`, unexpected flags and invalid upper bits. A reviewed contract cannot substitute `UInt32` for a source `Char` even though both use the same C width.

## Installed checks

```sh
bash scripts/build-lean-link-spike.sh --link-only
node --test tests/component-char-contract.test.mjs
LEAN_BRIDGE_TYPE_CORPUS_BROWSERS=chromium,firefox,webkit \
  node --test tests/component-char.test.mjs
node --test tests/component-scalars.test.mjs
```

The contract checks exhaust the Unicode code-point range. A real wasm32 runtime validates every value from zero through `0x110000`, plus oversized 64-bit slots, invalid flags and mismatched tags. Invalid decoded results and rejected host inputs release their call arenas.

The installed suite compiles fresh Lean, including the fixture's two theorems, for ordinary-source and compiler-checked reviewed contracts. It installs exact npm archives offline after renaming the original project path. Consumer calls run with Lean and C compilers absent from `PATH`.

Each path passes 1,126 public-API assertions in Node and in each of three browser contexts: a plain page, React StrictMode and a dedicated worker. The browser runs cover Chromium 151.0.7922.34, Firefox 153.0 and WebKit 26.5. Strict TypeScript checks all five public signatures, rejects a numeric Char signature, and executes five additional typed calls. The existing scalar package suite also passes, including all previously supported scalar types and the added Char examples.

`build/char-npm/report.json` records the two source paths, host versions, results and archive receipts. Each path's component/runtime archives and receipt live under `build/char-npm/`. Downstream CI executes the suite and retains these artifacts.

Regression checks pass: 1,161 core tests with 59 capability-gated skips, 65 documentation checks, 30 inventory checks, 111 site checks, lint, both typechecks and the production site build. The ordinary and reviewed Node/TypeScript corpus runs each record 248 catalog cases across two independent libraries: 224 executed cases and 24 explicit unsupported cases. These corpus runs retain their original sixteen-primitive scope; the separate Char suite supplies this milestone's new evidence.

## Recorded scope

The inventory adds 20 installed cells: Char parameter and result positions, ordinary-source and reviewed-IR paths, across Node JavaScript, Node TypeScript, browser JavaScript, React and browser workers. It does not promote Char fields, arrays, callbacks, returned functions, native hosts or PHP-Wasm. USize and ISize remain separate work in VO1218.

Shared native admission now rejects Char explicitly. The original sixteen-scalar native conversion branches are unchanged. Refreshed source hashes retain their earlier installed acceptance scope; this milestone does not repeat every historical native matrix. Separate contract regressions check the native rejection paths, including Python's older resource-oriented generator, which must not default Char to a numeric host type.

No registry release or production deployment is part of this milestone.
