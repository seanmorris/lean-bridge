# C exact integers through GMP

The ordinary-source and independently reviewed C packages each pass 47,037
installed assertions. The executable repeats those checks after relocation and
removal of the headers, consumer sources and archive handoff. The
[acceptance record](c-gmp-20260919.json) retains the tested archive, compiler-model,
receipt, consumer, executable and dependency identities.

## Public values

Lean `Nat` and `Int` use GMP `mpz_t` in direct calls, arrays, copied records,
primitive callbacks and returned closures. Callers initialize integer outputs
before use. Inputs are borrowed `mpz_srcptr` values; outputs are `mpz_ptr` values.
Generated aggregate `_init` functions initialize nested integers. `_clear`
releases owned storage and leaves initialized empty fields, so repeated clear
is safe. Successful calls replace initialized copied outputs; failed calls leave
them unchanged. Callback outputs are already initialized for assignment with
`mpz_set`.

The prepared C API has a separate adapter library. C++, Python, Rust and the
other native projections retain the existing private C transport. No shared
limb-buffer ABI was changed.

## Supplied dependency

The builder uses GMP 6.3.0 from the pinned upstream archive, without a download
or system GMP installation. Its detached signature was verified against GNU's
keyring with key `343C2FF0FBEE5EC2EDBEF399F3599FF828C67298`.
The archive SHA-256 is
`a3c2b80201b89e68616f4ad30bc66aee4927c3ce50e33929ca819d5c43538898`.

Each independent producer build configures a shared, position-independent x86-64
library with runtime CPU dispatch and runs GMP's upstream `make check` suite.
Prepared packages include `gmp.h`, `libgmp.so.10`, the complete corresponding
source, licenses, file hashes and configure flags. CMake and pkg-config select
the packaged dependency. The generated header normalizes its build path and is
marked as a system header, keeping upstream warnings separate from fatal
consumer conversion diagnostics.

Installed checks verify the source archive and every dependency receipt entry,
then confirm that the source-free executable loads its relocated GMP library.
GMP remains dynamically replaceable. See the [redistribution instructions](../publish/c.md#gmp-dependency-and-redistribution).

## Acceptance

- Zero and exact boundaries at 31, 32, 53 and 64 bits, signed values and
  16,385-bit integers survive copied calls and primitive callable positions.
- Negative `Nat` values reject in direct calls, arrays, nested fields and
  callback results. Existing outputs remain unchanged; later valid calls work.
- Initialized outputs can be replaced or alias their input. `mpz_set` creates
  independent values. Nested clear releases array elements and record fields.
- The 16 MiB conversion limit applies to integers and nested copied storage.
  Callback failures preserve their messages through cleanup, including embedded
  NUL. A successful call does not erase a previous error message.
- Each installed path passes 25 private-ABI allocation checks and 12 GMP-adapter
  allocation checks. Each nested-record fixture passes 25 additional GMP-adapter
  checks. These probes fail the adapter's allocations, not GMP's allocator.
- Two invalid installed consumers reject integer literals in pointer positions
  and attempts to construct the old public limb-buffer representation.
- Existing C callable checks retain expired-borrow, reentry, wrong-thread,
  signature, explicit disposal and registry-exhaustion coverage.

The independent Shop and Telemetry corpora compare C results with fresh Lean
oracles on both source paths. C executes 94 positive catalog cases and four
negative-Nat runtime cases; 26 invalid programs fail compilation. Both pkg-config
and CMake executables repeat their checks after source removal. Ordinary C++
corpus execution also checks that the shared private ABI remains compatible.
Separate scalar and nested-value suites rebuild archives in different
directories and require identical bytes.

Local checks use GCC 12.2.0 and glibc 2.36. The declared package and CI floor
remains glibc 2.38. GMP allocation failure aborts under its default allocator;
the bridge does not install global allocation hooks. The conversion budget is
not a bound on Lean or GMP working memory. See [GMP allocation behavior](https://gmplib.org/manual/Custom-Allocation).

This record covers C exact integers, not compound callable arguments, resources
or asynchronous delivery. Other profiles retain their own evidence.
